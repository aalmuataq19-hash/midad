# مِداد القاضي — نسخة Render

خادم Node واحد بلا اعتماديات تشغيل: يقدّم الصفحة ويعمل وسيطًا يحمل مفتاح API.

## الملفات
- `app.src.jsx` **المصدر** — هنا تُعدَّل الواجهة
- `app.js` الناتج المترجم — **لا يُعدَّل يدويًا**
- `src/prompts.js` نصوص التوجيه ومخططات المراحل الست — **مصدر واحد** للموقع ولأمر `/midad-analyze`
- `src/providers.js` جدول المزوّدين والقائمة البيضاء — يقرأه التطبيق والخادم معًا
- `src/json-repair.js` قراءة إجابة النموذج وإصلاحها
- `src/pdf-quality.js` كشف النص المبعثر في PDF العربي
> الملفات الأربعة في `src/` يضمّها البناء داخل `app.js`، ويستدعي `server.js` منها `providers.js` مباشرة.
- `server.js` الخادم والوسيط
- `index.html` الصفحة
- `test/` اختبارات وحدة، `test-fixtures/` قضية وهمية للتجربة

## الأوامر
```
npm install      # يثبّت esbuild (اعتمادية تطوير فقط)
npm run build    # يبني app.js من app.src.jsx
npm test         # ٨٢ اختبارًا: قراءة JSON، المزوّدون، القائمة البيضاء، الحجب، جودة PDF، الوسيط
npm start        # يشغّل الخادم محليًا
```
> بعد أي تعديل على `app.src.jsx` شغّل `npm run build`، وارفع الملفين معًا في نفس الـ commit.

## ملاحظات أمنية مثبّتة في الكود
- **الملفات المقدَّمة قائمة بيضاء** (`index.html`، `app.js`، `library/anzima.json`)؛ ما عداها ٤٠٤.
- **عناوين المزوّدين قائمة بيضاء** تُشتق من `src/providers.js`؛ لا يُبنى عنوان من ترويسة الطلب (منعًا لـ SSRF).
- **تمرير مفتاح شخصي إلى مزوّد آخر يشترط كلمة مرور الموقع**، وإلا صار الخادم وسيطًا مفتوحًا للعالم.
- **المفاتيح لا تُخزَّن ولا تُسجَّل**، وتُنقّى من كل نص خطأ قبل عرضه.
- **`Content-Security-Policy`** تبدأ من `default-src 'none'`، والنص المضمّن في `index.html` يمرّ ببصمة SHA-256 تُحسب من الملف عند الإقلاع.
- **الحد من الطلبات** بآخر قيمة في `x-forwarded-for` لا أولها.

نتيجة التدقيق الكامل وحالة كل بند في `AUDIT.md`.

# النشر التلقائي — طريقتان، اختر واحدة

## الطريقة الأولى (الأسهل والموصى بها): اربط GitHub بـ Render مباشرة

هذه تجعل Render ينشر وحده عند كل دفع على `main`، بلا أي إعداد إضافي.

1. افتح **https://dashboard.render.com** وسجّل الدخول.
2. من القائمة اليمنى اضغط **Services**، ثم اضغط اسم الخدمة **midad-al-qadi**.
3. من القائمة الجانبية داخل الخدمة اضغط **Settings**.
4. انزل إلى قسم **Build & Deploy**، وابحث عن سطر **Repository**.
5. اضغط **Connect Repository** (أو **Update** إن كان فيه مستودع قديم).
6. تظهر لك نافذة GitHub. اضغط **Configure account** ثم اختر حسابك **aalmuataq19-hash**.
7. في صفحة GitHub اختر **Only select repositories**، ثم من القائمة اختر **midad**، ثم اضغط الزر الأخضر **Install & Authorize** (أو **Save** إن كان مثبتًا من قبل).
8. تعود إلى Render. اختر المستودع **aalmuataq19-hash/midad**، والفرع **main**، ثم اضغط **Save Changes**.
9. في نفس قسم **Build & Deploy** ابحث عن **Auto-Deploy** واجعله **Yes** (أو **On Commit**)، ثم **Save Changes**.
10. للتأكد: افتح تبويب **Events** في الخدمة، ويجب أن يظهر نشر جديد خلال دقيقة من أي دفع.

**إن لم تجد الخيار أو تعثّرت في الخطوة 6 أو 7، انتقل إلى الطريقة الثانية.**

## الطريقة الثانية: Deploy Hook مع GitHub Actions

ملف النشر جاهز في المستودع: `.github/workflows/deploy.yml`. ينقصه سرٌّ واحد فقط.

**أولًا: انسخ رابط النشر من Render**

1. افتح **https://dashboard.render.com** ← **Services** ← **midad-al-qadi**.
2. اضغط **Settings** من القائمة الجانبية.
3. انزل إلى قسم **Deploy Hook**.
4. اضغط **Copy** بجانب الرابط. (الرابط سرّي؛ من يملكه يستطيع طلب نشر. لا تضعه في أي رسالة ولا في أي ملف.)

**ثانيًا: ضع الرابط سرًّا في GitHub**

5. افتح **https://github.com/aalmuataq19-hash/midad**.
6. اضغط تبويب **Settings** في أعلى صفحة المستودع (وليس إعدادات حسابك).
7. من القائمة اليمنى اضغط **Secrets and variables**، ثم منها اضغط **Actions**.
8. اضغط الزر الأخضر **New repository secret**.
9. في خانة **Name** اكتب بالضبط: `RENDER_DEPLOY_HOOK`
10. في خانة **Secret** الصق الرابط الذي نسخته من Render.
11. اضغط **Add secret**.

**ثالثًا: جرّبها**

12. في صفحة المستودع اضغط تبويب **Actions**.
13. اضغط اسم **نشر على Render** من القائمة اليمنى.
14. اضغط **Run workflow** ثم **Run workflow** مرة أخرى في النافذة الصغيرة.
15. بعد دقيقة تقريبًا تصير العلامة بجانب التشغيل **✓ خضراء**. افتح Render ← **Events** لترى النشر الجديد.

من الآن، كل دفع على `main` سيشغّل هذا الملف تلقائيًا.

### ماذا يفعل هذا الملف قبل أن ينشر
1. يثبّت الاعتماديات.
2. يشغّل اختبارات الوحدة (`npm test`).
3. يتأكد أن `app.js` المرفوع **مطابق** لما يتولد من `app.src.jsx`، ويوقف النشر إن نُسي البناء.
4. يفحص أن لا مفتاح API مكتوب داخل المستودع.
5. عندها فقط يطلب النشر من Render.

فإن ظهرت علامة **✗ حمراء** في تبويب Actions، فمعناها أن أحد هذه الفحوص فشل، ولم يُنشر شيء.
